🌐 Antigravity Mesh: Спецификация архитектуры коробочного решения (Turnkey Edition)
1. Концепция и цели продукта
Цель: Предоставить любому пользователю возможность развернуть персональный или управляемый узел Antigravity Mesh за одну команду (One-Line Install & Zero-Config MCP), без необходимости вручную настраивать домены, открывать порты роутера или возиться с SSL-сертификатами, с сохранением возможности 100% автономной установки для опытных администраторов.


________________


2. Архитектура решения и два режима работы
[Режим 1] Быстрый старт: Cloud Gateway + Reverse Tunnel (Рекомендуемый)
Архитектура для большинства пользователей (домашние ПК за NAT/роутером, VPS с серыми IP, рабочие станции без белого IP):


* Сетевой шлюз (Master Gateway): Развернут на основном сервере (*.mcp.yourdomain.com) с единым Wildcard SSL-сертификатом Let's Encrypt (DNS-01 challenge).
* Reverse Agent на хосте пользователя: Лёгкий исходящий RPC-туннель (FRP / Chisel), не требующий входящих портов и белого IP.
* Централизованный FastMCP: Мастер-сервер принимает запросы от LLM (Gemini / Claude), формирует динамические промпты и ресурсы, а команды bash_exec транслирует через защищенный туннель локальному агенту.
* Персональный адрес: Каждой ноде автоматически выделяется субдомен вида https://<node-name>.mcp.yourdomain.com/sse.
* Преимущества: Нулевая конфигурация, мгновенные обновления логики и скилла на стороне шлюза.
[Режим 2] Полный Standalone (Для опытных / Автономный режим)
Архитектура для изолированных серверов, закрытых контуров и пользователей с собственными доменами:


* Полный стек FastMCP + SSE-демон запускается локально на машине пользователя.
* Подрежимы сети:
   1. Свой домен (FQDN): Автоматический подъем Caddy Reverse Proxy с выпуском сертификата Let's Encrypt через HTTP-01 challenge.
   2. Прямой IP + Self-Signed TLS: Генерация OpenSSL SAN-сертификата под реальный IP хоста, HTTPS на порту 8443.
   3. Прямой IP + Plain HTTP: Локальный порт 8096 без веб-серверов.
* Преимущества: Полный суверенитет данных, независимость от внешней инфраструктуры.

3. Автоматическая доставка скилла через протокол MCP (In-band Delivery)
Для исключения ручного копирования системных инструкций в интерфейсы ИИ реализованы три механизма MCP:


1. MCP Prompts (prompts/list, prompts/get):
   * Регистрация промпта antigravity-orchestrator.
   * Автоматическая передача системной роли Autonomous Remote Infrastructure Orchestrator при старте диалога.
2. Динамический MCP Resource (resources/list, resources/read):
   * Публикация ресурса resource://skills/orchestrator.md.
   * Шаблон скилла интерполируется на лету реальными параметрами текущей системы: хостнейм, реальные сетевые адреса, топология сети, лимиты памяти и список доступных узлов.
3. Fallback-инструмент (Self-Bootstrapping Tool):
   * Инструмент get_orchestration_skill() для MCP-клиентов, поддерживающих только функциональные вызовы (tools).

4. Структура проекта в репозитории
antigravity-mesh/


├── install.sh                  # Единый интерактивный мастер установки (CLI Wizard)


├── Makefile                    # Сборка, тесты, линтинг и упаковка релизов


├── core/


│   ├── __init__.py


│   ├── server.py               # FastMCP-сервер (SSE transport, tools, resources, prompts)


│   ├── agent.py                # Легковесный RPC-агент для режима «Туннель»


│   └── vitals.py               # Модуль сбора телеметрии хоста (CPU, RAM, Disk, Services)


├── skills/


│   └── orchestrator.md         # Шаблон скилла, раздаваемого через MCP


├── templates/


│   ├── caddy.Caddyfile.j2      # Шаблон обратного прокси Caddy


│   └── agy.service.j2          # Шаблон systemd-службы демона


└── tests/                      # Набор автотестов (TDD)


    ├── test_installer.sh       # Проверка аргументов командной строки и dry-run


    ├── test_mcp_endpoints.py   # Тестирование инструментов и ресурсов FastMCP


    └── test_vitals.py          # Тестирование сбора телеметрии

5. Модель безопасности
* Авторизация по криптографическому токену Bearer <token> (openssl rand -hex 16).
* Ограничение путей файловых операций (ALLOWED_PATHS).
* Возможность запуска агента от непривилегированного пользователя с sudo-правилами только для разрешённых команд.
