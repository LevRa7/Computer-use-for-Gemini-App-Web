## 🚀 Antigravity Mesh v0.2.3

Релиз, после которого mesh работает из **Gemini Spark**: ответ на вызов инструмента
доставляется ровно один раз, а узел адресуется через **один общий домен**.

### 🛠️ Доставка MCP — тот самый фикс «хост не ответил»

- **`/sse` и `/mcp` отвечают только телом POST.** Дублирование того же ответа в
  SSE-поток вызывало отказ сессии у строгого streamable-HTTP клиента: команда уже
  выполнялась на узле, а модель не получала результат и отдавала `DEADLINE_EXCEEDED`
  через 60 с с пустым сообщением.
- **Уникальный `Mcp-Session-Id` на каждый `initialize`** вместо общего имени
  пользователя: `DELETE` от одного из параллельных фронтендов Google больше не
  выглядит как завершение сессии, в которой летит чужой ответ.
- **Потоки `GET /mcp` несут только JSON-RPC кадры** — без legacy-кадра
  `event: endpoint`, указывающего на `/messages`.
- **Ненулевой exit code больше не читается как «узел недоступен»**: в тексте прямо
  сказано, что команда выполнилась на хосте, а код — её собственный статус.
- Логирование по каждому ответу: тело или сколько живых потоков его получили.

### 🌐 Адресация — один общий домен

- Все узлы доступны через `<общий-домен>/sse?user=<имя-узла>&token=…`; ни
  субдоменов на устройство, ни отдельных DNS-записей, ни SAN в сертификате.
- Регистрация больше не возвращает `subdomain`; старые субдоменные ссылки
  продолжают работать и пишут предупреждение в лог.

### 🧰 Эксплуатация

- `deploy_gateway.sh` — единственный поддерживаемый путь публикации шлюза:
  sha256-манифест с проверкой на хосте, бэкап с меткой времени, рестарт и
  публичная проверка здоровья.
- `ops/nginx/` — сниппет шлюза теперь версионирован, включая `Connection ""` на
  HTTP-эндпоинтах и `keepalive_timeout 0`: chunked-терминатор `DELETE` от фронтенда
  Google парсился как строка запроса (`"0" 400`, 79 раз за 12 минут) и рвал
  соединения вместе с летящими запросами клиента.
- `GEMINI_APP_INSTRUCTIONS.md` — готовый текст инструкций для приложения: реальный
  набор инструментов (прежний текст требовал `matebook_exec`/`<node>_exec`, которых нет).
- Скиллы больше не требуют инструментов, отсутствующих в этом MCP.
