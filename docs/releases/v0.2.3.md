## 🚀 Antigravity Mesh v0.2.3

The release that makes the mesh work from **Gemini Spark**: a tool answer is now
delivered exactly once, and a node is addressed through **one shared domain**.

### 🛠️ MCP delivery — the "the host did not answer" fix

- **`/sse` and `/mcp` answer in the POST body only.** Duplicating the same response
  on the caller's SSE stream made a strict streamable-HTTP client reject the
  session: the command had already run on the node while the model never received
  the result, and it reported `DEADLINE_EXCEEDED` after 60 s with an empty message.
- **A unique `Mcp-Session-Id` per `initialize`** instead of the shared user name:
  a `DELETE` from one of Google's parallel frontends no longer looks like it
  terminated a session that had an answer in flight.
- **`GET /mcp` streams carry JSON-RPC frames only** — no legacy `event: endpoint`
  frame pointing at `/messages`.
- **A non-zero exit code no longer reads as an unreachable node**: the result says
  the command ran on the host and the code is the command's own exit status.
- Per-response logging: the body-only path versus how many live streams received it.

### 🌐 Addressing — one shared domain

- Every node is reached through `<shared-domain>/sse?user=<node-name>&token=…`;
  no per-device subdomain, no per-device DNS record, no per-device TLS SAN.
- Registration no longer returns a `subdomain`; legacy subdomain URLs keep working
  and log a deprecation warning.

### 🧰 Operations

- `deploy_gateway.sh` — the supported publish path for the gateway: an sha256
  manifest verified on the host, a timestamped backup, a restart and a public
  health check. Nothing is installed when verification fails.
- `ops/nginx/` — the gateway snippet is versioned, including `Connection ""` on the
  HTTP endpoints and `keepalive_timeout 0`: the chunked `DELETE` terminator from
  Google's frontend was parsed as a request line (`"0" 400`, 79 times in 12
  minutes) and killed connections with the client's requests still in flight.
- `GEMINI_APP_INSTRUCTIONS.md` — drop-in app-side instructions naming the real tool
  surface; the previous text mandated `matebook_exec` / `<node>_exec` / `gdrive_copy`,
  which this MCP does not have.
- Skills no longer instruct the model to call tools that do not exist.
