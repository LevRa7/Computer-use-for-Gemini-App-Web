## 🚀 Antigravity Mesh v0.4.0

**A phone is now a full node — and it can be driven, not just commanded.** The
same installer that puts a node on a PC runs inside Termux on an unrooted Android
phone, and from there Gemini can read the device (battery, signal, time zone,
language, sensors, CPU, RAM, network, cameras, microphones) and act on it (torch,
volume, clipboard, notifications, camera, microphone, location, SMS) through four
purpose-built tools with a consent policy that respects the person holding the
phone. Both features that were sitting unreleased — the gateway's command gate and
the Termux support — ship here as well.

### 📱 The device branch (four tools)

| Tool | What it does | Confirmation |
| :--- | :--- | :--- |
| `device_info` | One-call device report: battery and charging, network interfaces with Wi-Fi and cellular signal, language, time and time zone, CPU, memory, storage, cameras, microphones, sensors, and what the platform can actually reach. | never asked |
| `device_control` | Twenty reversible actions: torch, vibrate, volume, brightness, text-to-speech, toast, notifications, clipboard, media, media scan, wake lock, download, open, share, dialog, wallpaper. | not asked |
| `device_capture` | Camera, microphone, location, fingerprint, USB, infrared. Photos and recordings stay in the node's capture directory and are never uploaded by themselves; `fingerprint` returns only the verdict; `usb_access` asks Android for permission and deliberately refuses to run a program for you. | **asked first** |
| `device_messages` | SMS, call log, contacts, placing a call — off until the operator sets `MESH_DEVICE_PIM=1`, because it is someone's private data. | **asked first** |

- **`core/device.py`** answers for one machine at a time. A single resolver decides
  `termux`, `linux`, `windows` or `darwin` — Windows first, then the Termux signals,
  then Darwin, else Linux — and a section × scenario matrix gives every section its
  own implementation per platform, so a phone never runs a desktop command and a
  laptop never runs a phone one. Nothing raises: a block the platform cannot answer
  says `available: false` with the reason and, where one exists, the fix, instead of
  a fabricated zero.
- **`core/termux.py`** is the only place that executes `termux-*` commands: argv
  lists (never a shell), a `termux-*` allowlist with path separators refused, a hard
  timeout per call, and `missing` / `denied` / `timeout` / `refused` mapped to a
  human fix. Android reports a refused permission as a *successful* call whose body
  is `{"error": "Please grant the following permission …"}` — that is now read as a
  refusal, and the permission is remembered in `capabilities().permissions`.
- **A proper report on every platform.** `system_info` carries the device blocks
  next to the old ones; `system_vitals` gains the battery and the thermal sensors;
  `mesh_status` adds `device_class`, `scenario` and `battery_percent`, so a model
  knows it is talking to a phone on a battery before it starts a build.
- **Background work survives the screen going off.** `run_job` takes Android's wake
  lock for the lifetime of the job and releases it exactly once per job — even
  though `job_kill` and the reaper both finish the same job — so stopping one job
  can never drop the protection of another one that is still running.

### 🐧 Android / Termux installation

**The phone is the node.** A phone is the one target that is neither "just Linux"
nor served by the Windows installer: the same `install.sh` runs inside
[Termux](https://termux.dev), root is **not** required, and the phone then appears
in Gemini Spark like any other machine — shell, files, background jobs, public
shares and, with this release, the device tools.

#### 1. Install Termux and its two add-ons

| App | Where | Why |
| :--- | :--- | :--- |
| **Termux** | [termux.dev](https://termux.dev) → [F-Droid](https://f-droid.org/packages/com.termux/) or [GitHub releases](https://github.com/termux/termux-app/releases) | the terminal the node lives in. **Do not use the Google Play build** — it is unmaintained and abandoned at an older version. |
| **Termux:API** | [F-Droid](https://f-droid.org/packages/com.termux.api/) or [GitHub releases](https://github.com/termux/termux-api/releases) ([wiki](https://wiki.termux.com/wiki/Termux:API)) | answers every `termux-*` command: battery, Wi-Fi and cellular signal, sensors, cameras, microphone, notifications, SMS. Without it the device tools only reach what Android exposes to an ordinary app (model, CPU, memory, thermals, locale, time, storage). |
| **Termux:Boot** | [F-Droid](https://f-droid.org/packages/com.termux.boot/) or [GitHub releases](https://github.com/termux/termux-boot/releases) | Android gives apps no boot hook; this one runs `~/.termux/boot/*` after a reboot, which is how the node comes back on its own. |

> [!IMPORTANT]
> Install Termux **and both add-ons from the same source**. An add-on shares
> Termux's `sharedUserId` and must be signed with the same key, so a Termux from
> GitHub plus a Termux:API from F-Droid is refused by Android with a plain
> "App not installed" — verified on Android 16, and the reason is not obvious from
> the error message.

Then open **Termux:API once** (Android will not let it answer until the app has
been launched) and, optionally, open **Termux:Boot** once for the same reason.

#### 2. Install the node

```bash
pkg update -y
curl -fsSL https://smart-server.online/install.sh | bash
```

The installer detects Termux and changes every step that differs on Android: `pkg`
instead of apt (there is no `sudo`), the per-user domain file instead of `/etc`, a
**node name taken from the device model** (Android answers `localhost` to every
app, and the gateway keeps one tunnel per name), and **runit**
(`termux-services`) plus a **Termux:Boot** entry instead of systemd. Pick a name
yourself with `bash -s -- --user=my-phone`.

#### 3. Make it survive Android

1. **Battery optimisation → Unrestricted** for Termux, Termux:API and Termux:Boot
   (`Settings → Apps → Termux → Battery`). On many OEM builds there is also an
   *autostart* / *protected apps* list that has to include Termux.
2. **Open Termux once after a reboot**, or set up Termux:Boot as above. Android can
   kill the whole Termux app when memory runs short, and neither runit nor
   Termux:Boot covers that — opening Termux once starts the supervisor again.
3. The boot script takes Android's wake lock; `run_job` re-takes it for the lifetime
   of every background job, so a build no longer stops when the screen goes off.

#### 4. Grant the permissions the device tools need

`Settings → Apps → Termux:API → Permissions`, then allow what you actually want to
use: **Camera**, **Microphone**, **Location** (needed for the Wi-Fi SSID and for
`termux-telephony-cellinfo` on Android 12+), **Phone**, **SMS**, **Call log**,
**Contacts**, **Notifications**, **Files/Photos**. Nothing else has to be granted,
and each tool answers with the exact permission that is missing instead of failing
silently.

#### 5. Use it

```bash
termux-setup-storage          # only if the node should reach /sdcard (photos, downloads)
```

Then, from Gemini: *"what is the battery level and the signal strength of my
phone?"* (`device_info`), *"turn on the torch"* (`device_control`), *"take a photo
and share it"* (`device_capture` + `share_file`). `MESH_DEVICE_PIM=1` in
`~/.config/antigravity-mesh/agent.env` additionally enables `device_messages`
(SMS, call log, contacts, placing a call), which stays off until you ask for it.

The full guide — autostart, logs, updates, uninstall, the private-gateway case and
a troubleshooting table — is [`docs/TERMUX.md`](../TERMUX.md).

### ⚙️ What Termux changed in the installer

- **The installer detects Termux** and changes every step that differs: `pkg`
  instead of apt (and no `sudo`), the per-user domain file instead of `/etc`, the
  node name from the **device model** (Android answers `localhost` to every app, and
  the gateway keeps one tunnel per name), and **runit** (`termux-services`) plus a
  **Termux:Boot** entry instead of systemd — there is no systemd on a phone.
- **Shared storage stays opt-in.** `/sdcard` is invisible until `termux-setup-storage`
  is run; the capture directory reports `shared: "absent"` with that exact fix
  instead of writing somewhere it cannot reach.
- **`docs/TERMUX.md`** is the full guide: permissions, autostart, the wake lock,
  where captures land, and a troubleshooting table — including the case that cost
  the most time on real hardware, *Android killed the whole Termux app*: neither
  runit nor Termux:Boot covers that, opening Termux once starts the supervisor again.

### 🔒 The confirmation policy, now with the phone's two sensitive tools

The gateway already gated the four classes that must never run silently — installs,
deletes, `sudo` and system paths — behind `system_change` / `system_write`, with
`bash_exec` / `run_job` / `write_file` / `edit_file` refusing those and pointing at
the confirmed twin. That work ships in this release too. On top of it, the device
branch adds a fourth annotation class for what observes the physical world or a
person's private data: `device_capture` and `device_messages` carry
`destructiveHint` **on purpose**, because that hint is the only one clients such as
Gemini Spark reliably turn into a *"confirm this action?"* prompt — a camera or an
SMS list that fires silently is worse than an honest over-classification.
`device_control` stays ordinary local work: marking a torch as destructive would
only train you to click through the prompts that matter.

### 🔧 What real hardware taught us

Captured on an OPPO PHY110 running **Android 16** (the fixtures live in
`tests/fixtures/termux/`, with their identities redacted):

- **An add-on must share Termux's signing key.** The F-Droid build of Termux:API
  cannot be installed next to a Termux installed from GitHub — Android refuses it.
  `docs/TERMUX.md` now says so, and the GitHub build installs cleanly.
- **The Wi-Fi answer names its channel `frequency_mhz`**, not `frequency`; the
  frequency was silently lost.
- **A refused permission is not an error exit code.** It arrives with exit code 0,
  which used to look like an empty answer — a phone with no cell data instead of a
  phone that needs one permission granted.
- **Thermal zones contain junk.** `mmw0 = -273000` (an unpopulated sensor) and
  `pm8550-bcl-lvl0 = 0` (a current-limit *level*, not a temperature) were reported
  as degrees; physically impossible values and `*-lvl*`/`*-bcl*` zones are now
  dropped rather than averaged into an answer.
- **The kernel page size is 4 kB** — worth checking before blaming an old APK, and
  `getconf`/`/proc/self/smaps` answers it without root.

### ⚙️ Operator switches

| Variable | Default | What it does |
| :--- | :--- | :--- |
| `MESH_DEVICE` | `auto` | `auto` keeps the branch advertised everywhere (only the answer changes), `0` switches it off, `1` forces it on. |
| `MESH_DEVICE_ACTIONS` | empty | Allowlist of action names for the three action tools. |
| `MESH_DEVICE_CAPTURE_DIR` | shared storage after `termux-setup-storage`, else the node cache | Where photos and recordings are written. |
| `MESH_DEVICE_PIM` | `0` | `1` enables SMS, call log, contacts and placing a call. |
| `MESH_DEVICE_QUICK` | `0` | `1` keeps `system_info` instant by skipping network, cameras, microphones and sensors. |
| `MESH_READ_ONLY` | `0` | Now also refuses every `device_control` / `device_capture` action and blocks `sms_send` and `call`. |
