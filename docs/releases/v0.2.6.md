## 🚀 Antigravity Mesh v0.2.6

A visual installer for Windows: the same variants as the console installer, in a
window, with a language switch and the MCP link at the end. Plus three defects the
wizard exposed in the Windows path.

### 🪟 Visual installer for Windows

`install-gui.cmd` (or `install-gui.ps1`) opens a WinForms wizard that needs nothing
but the PowerShell 5.1 already present on Windows — no Python, no Node.js, no
administrator rights.

- **Quick setup** — node name = PC name, shared gateway domain, Windows autostart.
- **Custom setup** — your own node name, your own shared domain, optional token.
- **Remote over SSH** — copy the node code to a Linux host and run `install.sh`
  there, the way `install.sh --ssh` does. Requires the Windows *OpenSSH Client*
  feature and key-based auth; password prompts are not supported.

The wizard **does not re-implement the installation**: it collects the options and
runs `install.ps1` with them, so node registration, the fail-closed check on an
empty token, the autostart entry and the shared-domain URL contract stay in one
place. The first screen runs `install.ps1 -DryRun` as a real preflight (Python,
`websockets`, the resolved domain, the config and autostart paths) and changes
nothing; before starting it shows the exact command line; during the run it streams
the installer output; at the end it shows the MCP link with a copy button, the
three-step Gemini instructions, the paths it created and the full log.

Implementation notes worth keeping:

- **The source is pure ASCII** and every user-visible string lives in
  `install-gui.strings.json`, read explicitly as UTF-8. PowerShell 5.1 decodes a
  BOM-less script with the ANSI code page, and Russian text then turns into
  characters the parser reads as string delimiters — the trap that forces
  `install.ps1` to carry a BOM. Keeping the source ASCII makes the wizard parse
  however the file was saved, and makes the language switch a data change.
- **The exit code is read from a process this code starts itself.** Measured on
  Windows PowerShell 5.1: `Start-Process -RedirectStandardOutput … -PassThru`
  returns an object whose `ExitCode` is **empty** once the process has exited, so
  an installer built on it cannot tell success from failure. Output is redirected
  by `cmd.exe` and the process is created through `ProcessStartInfo` instead.
- **The layout is absolute pixels with `AutoScaleMode = None`**, and buttons size
  themselves to their label: a fixed width clipped the longer Russian labels.

### 🌐 Language selection

The wizard starts in the language of the user's Windows settings and can be
switched live in the header; `-Lang ru` / `-Lang en` overrides the detection.

Two real bugs were fixed here:

- **`-Lang` never reached the script.** The internal language variable was called
  `$script:Lang`, and at script scope that *is* the `$Lang` parameter, so the
  initialiser `$script:Lang = 'en'` overwrote whatever `-Lang` had bound. Because
  `'en'` is truthy, the detection branch then never ran at all: the wizard always
  started in English. The internal variable is now `$script:UiLang`.
- **Detection looked at the wrong signal.** `CultureInfo.CurrentUICulture` is not a
  reliable answer on Windows: on the machine this was developed on, Windows is
  Russian (`PreferredUILanguages` = `ru-RU`, `InstalledUICulture` = `ru-RU`,
  `CurrentCulture` = `ru-RU`) while the process reports `CurrentUICulture` =
  `en-US`. The wizard now reads the user's language list from the registry first —
  `PreferredUILanguages`, then `International\User Profile\Languages`, then
  `Get-WinUserLanguageList` — and uses the process culture, the OS install language
  and the regional format only as fallbacks.

### 🔗 Result page

- The Gemini address in step 1 is a **real link**: clicking it opens
  `https://gemini.google.com/spark/apps`, and the button beside it copies the
  address. It used to be a plain label, so it could be neither clicked nor copied.
- The MCP link keeps its copy button and its own confirmation.

### ✅ Tests

`36 passed` for the installer suites (`tests/test_installer_gui.py` plus the
extended domain audit), and the wizard's own headless `-SelfTest` runs 19 checks:
every page built in both languages and in every variant, the process pipeline
capturing output and distinguishing the exit code, the URL parser (including the
`agent.env` fallback), the preflight parser, live-switching chrome, the clickable
link, control overflow, and language detection.

New regression guards specifically for the defects above:

- `test_explicit_lang_reaches_the_script` — `-Lang ru` / `-Lang en` must be
  observable in the running script.
- `test_start_language_is_detected_when_no_flag_is_given` — without the flag, the
  language used must equal the language detected.
- `test_detection_reads_the_user_language_list_not_only_the_process_culture`.
- `test_gui_files_do_not_name_the_project_domain`, and `install-gui.*` added to the
  existing single-source audit.
