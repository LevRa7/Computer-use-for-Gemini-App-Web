## 🔧 Antigravity Mesh v0.4.3

One installer defect, found by the continuous integration that had been red
since v0.4.1: the Android log directory could be left with a logger that cannot
run. Nothing else changed.

### 📱 `log/run` is never a dangling link

`configure_termux_node` enables runit supervision when `sv` and `runsvdir` are
present, and gives each service the logger runit requires: a symlink to
termux-services' `svlogger`, or a small script when `$PREFIX` refuses symlinks.

The link was created without checking that its target exists. `ln -sf` succeeds
against a missing file, so a phone where the runit commands are present but
`termux-services` did not install `svlogger` ended up with a **dangling**
`$PREFIX/var/service/<node>/log/run` — a logger runit cannot execute, and a
`Path.exists()` that is false for a link that does exist.

- The symlink is now created only when `svlogger` exists; otherwise the
  equivalent script is written, exactly as in the symlink-refused case.
- `tests/test_termux_support.py::test_a_full_termux_install_lays_out_runit_and_the_boot_entry`
  passes on every platform again, which is what the red CI runs were reporting
  (`CI` failed from v0.4.1 through v0.4.2 with `1 failed, 1136 passed`).

The release workflow was unaffected because its verify job runs only
`tests/test_updater.py` and `tests/test_version_single_source.py`, so v0.4.2
shipped with the defect; this release carries the fix.
