## 🚀 Antigravity Mesh v0.2.5

The Windows release: the node was only ever exercised on Linux, and running the
suite on Windows 11 with PowerShell 5.1 turned up a set of real defects. It also
makes the public domain a single setting, and brings public file sharing into the
repository.

### 🪟 Windows correctness

- **Readable non-ASCII output.** Captured child output is decoded as UTF-8, then
  the OEM console code page, then ANSI — instead of the process locale. Before
  this, `echo привет` arrived as `ЇаЁўҐв` and localised error text was unreadable;
  python children are now told to speak UTF-8, and job logs are decoded the same
  way. Line endings are normalised, so pagination cursors still line up.
- **Real telemetry.** `system_vitals` reported `1 MB` total RAM and a flat `0.0`
  CPU load on Windows; it now uses `GetSystemTimes` for utilisation and
  `GetTickCount64` for uptime.
- **`job_kill` on a finished job** reported a failure (`taskkill` exits non-zero
  for a process that is already gone). It is now treated as already stopped, and
  `taskkill` runs without a console window.
- **`write_file` with `mode`** silently claimed success while Windows ignored the
  permission bits; the result now reports `mode_applied` and explains why.
- **`install.ps1`** parses under Windows PowerShell 5.1: the repository copy keeps
  its UTF-8 BOM (a BOM-less script is decoded as ANSI and the Russian strings turn
  into smart quotes that break the parser), a mis-indented here-string terminator
  is fixed, and registration now **fails closed** — a node that cannot register no
  longer leaves an empty config and a broken autostart behind.
- **`run_tests_windows.ps1`** runs the suite on Windows, including the pywin32
  paths the MCP SDK needs on `PYTHONPATH`.

### 🌐 One place for the domain

- `core/domain.py` declares the public domain once; the node, the gateway,
  `core/web_share`, `core/mcp_tools` and `agy_sync`/`agy_watcher` all resolve it
  there, in this order: `MESH_PUBLIC_URL` → `AGY_PUBLIC_BASE_URL` → `domain.env` →
  legacy `MESH_GATEWAY` → the single built-in default.
- `domain.env` is the one setting per host (`/etc/antigravity-mesh/domain.env`,
  `%USERPROFILE%\.config\antigravity-mesh\domain.env`).
- The installers carry a `__MESH_DOMAIN__` placeholder and refuse to run when no
  domain is configured; `deploy_gateway.sh` bakes the resolved domain into the
  published copies, writes `domain.env`, and puts `core/domain.py` next to the
  gateway.
- `ops/mesh-domain.sh` is the shared shell resolver; `ops/nginx/` gains a vhost
  template plus `render-domain.sh` (`--out` / `--check` / `--apply`).

### 📤 Public file sharing

- `core/web_share.py` plus four tools — `share_file`, `serve_dir`, `share_list`,
  `unshare` — bringing the surface to 19 tools. `serve_dir` serves a directory in
  place, read-only, and never deletes it on `unshare`.
- The gateway gains the public route `/<node>/<slug>/…` (`public_share_endpoint`)
  and its `SHARE_TOOL_SPECS`; published links are built from the single domain.
- Limits raised: 32 MiB per file by default, 64 MiB ceiling via
  `MESH_WEB_MAX_BYTES`, and the gateway's websocket message cap set to 128 MiB so
  the transport can carry a ceiling-sized payload. The old 8 MiB default was the
  real ceiling for shares, not the transport.

### 🛠️ Gateway and nginx fixes

- The installer responses carried **two** `Content-Type` headers
  (`add_header Content-Type` appends rather than replaces), which let a client
  treat the script as binary; the snippet now uses `default_type text/plain`.
- The registration branch that reuses an existing node by MAC address raised
  `NameError: name 'user' is not defined` and answered HTTP 500 — every
  re-registration of a known machine failed.
- The gateway vhost no longer declares `/ws/tunnel` twice.

### ✅ Tests

`212 passed, 1 skipped` with `run_tests_windows.ps1`. On Windows this repository
started at `87 passed, 12 failed`. New suites: `test_domain`,
`test_domain_single_source`, `test_web_share`, `test_gateway_share_route`.
