# 🌐 Antigravity Mesh: Distributed Node Dispatcher (SKILL.md)

Настоящий скилл определяет порядок управления распределённой сетью Linux-узлов напрямую через нативный протокол MCP.

---

## 🧭 1. Динамическое обнаружение узлов (Zero Hardcoded Specs)
В системе **запрещено** использовать захардкоженные IP-адреса, домены, имена машин и спецификации оборудования. Вся топология определяется динамически:
1. **Телеметрия хоста:** инструмент `system_vitals()` возвращает загрузку CPU, память и дисковое пространство текущего хоста.
2. **Карта сети и факты:** файл `server_facts.json` содержит актуальный список узлов, их роли и метрики (читается через `read_file`).
3. **Подгрузка скилла через MCP:** вызов инструмента `get_orchestration_skill()` или чтение ресурса `resource://skills/dispatcher.md` возвращает актуальный текст данной инструкции.

---

## 🛠️ 2. Реальные инструменты этого MCP (сверено с `tools/list`)

> ⚠️ **В этом MCP НЕТ инструментов `<node>_exec`, `matebook_exec`, `debian_exec`,
> `racknerd2_exec`, `<node>_vitals` и `gdrive_copy`.** Они остались только в legacy-сервере
> `agy_mcp_server.py`, который нигде не запущен. Вызов такого имени возвращает
> `{"code":-32601,"message":"Unknown tool: ..."}`, и клиент показывает это как
> «не удалось получить ответ от хоста». Используйте только имена из таблицы ниже.

| Инструмент | Назначение |
| :--- | :--- |
| `bash_exec(command)` | Команды на узле, к которому подключён MCP (короткие, ≤25 с) |
| `list_dir(path)` | Содержимое каталога |
| `read_file(path, start_line, end_line)` | Чтение файла построчно |
| `write_file(path, content)` / `edit_file(path, old_string, new_string)` | Запись / точечная правка |
| `grep_search(pattern, path)` / `glob_find(pattern, path)` | Поиск по содержимому / по именам файлов |
| `system_vitals()` | CPU, RAM, диск |
| `system_info()` | Сводка по хосту одним вызовом |
| `mesh_status()` | Подтверждение, что узел на связи (вызывать, если кажется, что хост офлайн) |
| `run_job(command)` → `job_output(job_id)` / `job_kill` / `job_list` | Долгие команды в фоне |
| `get_orchestration_skill()` | Актуальный текст этого скилла |

> ⚡ **Таймауты:** команда дольше ~25 с обрывается шлюзом. Всё долгое (сборки, установки, тесты,
> скачивания) запускать через `run_job` и забирать результат через `job_output`.

## 🔒 3. Политика исполнения и шлюз проверки (Hard Error Gate)
1. **Запрет очередей Google Диска:** Файлы `antigravity_tasks.json` ликвидированы во избежание состояний гонки (race conditions). Команды в Google Диск не пишутся.
2. **Фиксация в мыслях (`<thought>`):** Обязательно логировать: имя инструмента MCP, пути, команду целиком, прочитанные/измененные файлы, целевой узел и время исполнения.
3. **Ориентация на результат:** Команда считается успешной только при `Exit: 0` и `isError: false`.
4. **Немедленный останов (Rollback & Halt):** При любой ошибке (`isError: true` или `exit_code != 0`) модель обязана железно остановиться, вернуть исходный текст ошибки и уведомить пользователя.
5. **Запрет симуляции:** При отсутствии инструмента MCP в текущей сессии прямо заявить об ошибке подключения («Инструменты MCP не зарегистрированы в текущей сессии»).
